# Chat Core Implementation Plan (chat plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every resbite gets a chat: people going (and the hosts) read and write it with the whole history, hosts send announcements, Resbite writes the system lines, messages arrive live with a push, and a one-off resbite's chat goes read-only 48 hours after its end.

**Architecture:** One migration adds the messages, a chat row per series, reads, mutes, the membership and closing rules, the read and write functions, system lines written by triggers in the same transaction as the event, two outbox kinds with a one-per-minute push rule decided when the message is written, and a Realtime broadcast trigger whose private channel `chat:<series_id>` carries only a signal. The app fetches through the functions after a signal, on focus, and every 20 seconds while the chat is open and its channel is not subscribed. A new `/chat` screen, a Chat row on the resbite, unread dots and announcement lines on My resbites, and push routing for a third payload type.

**Tech Stack:** Postgres 17 (Supabase; Realtime broadcast from the database), Deno edge function `deliver-notifications`, Expo SDK 57 / expo-router 57 / React Native 0.86, `@supabase/supabase-js` 2.116 (channels), node:test, Playwright 1.63 (`page.routeWebSocket`, `page.clock`).

**Spec:** `docs/superpowers/specs/2026-11-10-groups-and-chat-design.md` (CH-D1–D6; CH-P1–P3, P5–P12, P14–P19; screens CH-01–CH-08; mockup `group-chat.html`). Plans 2 (`2026-11-11-chat-2-groups.md`) and 3 (`2026-11-11-chat-3-safety.md`) build on this one; the three ship in **one release** (roadmap `2026-11-11-roadmap-connections-groups-chat.md`, Phase 3).

**Branch:** `ch1-core` from `main` after the circles-of-trust plan is merged (this plan copies functions from the circles migration).

## Global Constraints

- House function shape: `private.x` security definer `set search_path=''` + thin `public.x` wrapper (security invoker), explicit revoke/grant to `authenticated` only; private tables RLS on with no policies; **the new public tables (`messages`, `chats`, `chat_reads`, `chat_mutes`) also get RLS on, no policies and no grants: the app reads only through functions** (as `public.connections` does, Ruling 5 of plan 1), so the block filter of plan 3 lives in one place. ## Decisions this plan makes (spec silent or builder's choice)

1. **System lines are written by triggers** on `public.attendees`, `public.plans` and `public.plan_admins`, in the same transaction as the change (CH rule 7). This replaces editing `respond`, `answer_phone_invitation`, `decide_join_request`, `change_plan_v4` and `appoint_admin` one by one. A system line stores `author_id null`, an `event` code and a `payload` (K-B2). `payload.actor` is the person who acted (`auth.uid()`, null when nobody did). Every other person in the payload is a uuid, and the reads resolve uuids to first names server-side. **The app words the line**, so plan 2 changes wording for groups without touching the server. The roll and account deletion set `resbite.system`, and the triggers then write nothing (K-S2).
2. **No direct reads of the chat tables** (Global Constraints). The spec's Data section lists a select policy on `messages`; the functions replace it.
3. **A chat row per series is created by an `after insert` trigger on `public.plans`** (covering create, Do this again and the roll), and backfilled for every existing series.
4. **Until plan 2 lands, a repeating series follows the one-off rules on its current occurrence.** Plan 2 redefines `private.chat_member` and `private.chat_closes_at`. The release never ships plan 1 without plan 2. Plan 2's roll also sets the roll flag. Until then a real roll still writes an `admin` line for each carried admin, so this plan tests the flag directly.
5. **Delete and Remove ask in place** ("Delete this message for everyone?" / "Remove this message?") with a red button and Keep; the spec names the actions, not the confirm.
6. **One push a minute is decided when the message is written (K-B3.1).** `send_message` takes the series' advisory lock. It then queues no `chat_message` row for a recipient who already has one for the series from the last 60 seconds. The first message in a minute is pushed and the rest are not, as CH-P7 says. This replaces the spec's claim-time rule. The cost (K-S1): when the first message is deleted before delivery, nothing that minute is pushed.
7. **Delete and Remove work after the close (K-S17, owner default).** Rule 4's "reading only" means no new messages. Moderation and a person's own words should not expire with the chat.
8. **A one-off's "ended" line is computed (K-S16).** The app shows "<title> ended" as a separator at the end time. Nothing writes it, so rule 7 holds. Groups keep plan 2's stored line.
9. **The pinned announcement is the latest announcement still `sent` (K-S12).** Removing or deleting it pins the one before. An announcement whose author deleted their account unpins the same way.
10. **A reply flipped within 10 minutes updates one line (K-S2).** A `joined` or `cant_go` line for a person within 10 minutes of their previous one updates that line. Its `created_at` stays, and the update sends a new signal.
11. **Time zones and the countdown (K-N4).** The closing line, the closed date and the change lines use the plan's zone, as `whenLine` does. Message stamps and day separators use the phone's zone, as any chat app does. The countdown floors whole hours, shows minutes under an hour, and says "in 1 minute" under a minute.
12. **The poll runs only while the channel is not subscribed (K-N6).** The spec leaves this to the builder. Focus, the return to the app and every signal still read.
13. **A host's own message is deleted, never removed (K-N12).** "Message removed by an admin" never shows on a host's own words.
14. **A deleted account's messages lose their author (K-N5).** They get `state='deleted'`, no body and `author_id null`, as the spec's Data section says.
15. **IDN hosts are not linked (K-N14, CH-R-A5).** A link whose host has a non-ASCII character stays plain text. The finding proposed showing the punycode host in the confirm. Not linking is safer against look-alike hosts, and it needs no punycode library on the phone.

## Review Focus

1. **A person who said Can't go on a one-off, with the chat open on their phone.** Expected: the next fetch is refused (`42501 'Not in this chat'`) and the hook removes the channel at once. The screen shows the closed-to-you state. No push and no body about later messages reaches them. A bare `{id, kind, state}` signal may still reach the open socket until its token refreshes (K-N1). Tests in Tasks 1, 2, 6 and 7.
2. **The same message sent twice by a phone that lost its connection mid-send.** Expected: one row and one push per recipient, even when the two sends run at once. A retry that arrives after the chat closed still returns the stored row. Tests in Tasks 2 and 5.
3. **A lively chat: five messages in one minute.** Expected: each other member has one `chat_message` outbox row that minute, the first message's, decided under the series lock. The rest arrive in the app with the unread dot. A `plan_changed` queued behind 120 chat rows is expanded in the first run. Tests in Tasks 2 and 4.
4. **A resbite that ended 47 hours 59 minutes ago, then 48 hours.** Expected: writing works, then `22023 'Chat closed'`. Reading, Delete and Remove still work. The closing line counts down in minutes in the last hour, and the screen turns to the closed card at zero without a refocus. Tests in Tasks 1, 2, 5 and 7.
5. **The Realtime socket never connects (network, policy, web).** Expected: new messages, removals and late lines still appear within 20 seconds while the chat is open, and on return to the app. Test in Task 7 (socket refused, `page.clock`).
6. **A host removes an abusive message while others have the chat open.** Expected: the body leaves every open screen through the signal, and within one poll on the poll-only path. The pinned card falls back to the previous announcement. Tests in Tasks 2, 6 and 7.
7. **A system line about someone other than the actor.** Expected: a host's approval of Mia reads "Mia joined", an appointment reads "Leo is now an admin", and the person themselves reads "You". Tests in Tasks 3 and 5.
8. **A pending invitee taps an "Everyone invited" announcement.** Expected: the event opens, never the gone note. Test in Task 8.

**Interfaces:**
- Produces (bootstrap only):
  - Default privileges, as hosted has them (K-S5): `alter default privileges in schema public grant all on tables to anon, authenticated, service_role;`, then the same statement with `sequences` and with `functions`. The ruling's one line becomes three statements, because Postgres takes one object type per statement.
  - The stub: `create schema realtime; create table realtime.messages (id bigint generated always as identity, topic text not null, extension text not null default 'broadcast', event text, payload jsonb, private boolean not null default true, inserted_at timestamptz not null default now()); alter table realtime.messages enable row level security; create function realtime.topic() returns text language sql stable as $$ select nullif(current_setting('realtime.topic', true), '') $$; create function realtime.send(payload jsonb, event text, topic text, private boolean default true) returns void` (inserts a row). Grants: `usage on schema realtime` and `select on realtime.messages` to `authenticated` (K-S6).
- Produces (migration):
  - `public.messages (id bigint generated always as identity primary key, series_id uuid not null, plan_id uuid not null references public.plans(id) on delete cascade, author_id uuid null references public.profiles(id) on delete set null, kind text not null check (kind in ('message','announcement','system')), audience text null check (audience in ('going','everyone')), event text null, payload jsonb null, body text null check (body is null or char_length(body) between 1 and 1000), client_id uuid null, state text not null default 'sent' check (state in ('sent','deleted','removed')), created_at timestamptz not null default clock_timestamp(), updated_at timestamptz not null default now(), unique (author_id, client_id))`.
    - Indexes `messages_series_idx (series_id, id)` and `messages_series_updated_idx (series_id, updated_at)`. The second serves `chat_messages_since`.
    - Trigger `messages_touch` before update on `public.messages` runs `private.messages_touch()`. It sets `new.updated_at := now()` on every update (Shared interfaces).
  - `public.chats (series_id uuid primary key, is_group boolean not null default false, last_message_id bigint null, last_message_at timestamptz null, pinned_message_id bigint null, message_count int not null default 0)`; trigger `plans_chat_row` after insert on `public.plans` runs `private.plans_chat_row()` (`insert … on conflict do nothing`); backfill `insert into public.chats(series_id) select distinct series_id from public.plans on conflict do nothing`. Task 2's trigger keeps `last_message_id`, `last_message_at`, `pinned_message_id` and `message_count`.
    - `is_group` is the group flag's one definition (CH-R-A6). Nothing in plan 1 sets it true, so every chat here follows the one-off rules (Decision 4). Plan 2 sets it: true for good on a repeating series, and its backfill. Plan 2 adds `stopped_at` as its own column.
  - `public.chat_reads (series_id uuid, user_id uuid references public.profiles(id) on delete cascade, last_read_id bigint not null, primary key (series_id, user_id))`, `public.chat_mutes (series_id uuid, user_id uuid references public.profiles(id) on delete cascade, muted_at timestamptz not null default now(), primary key (series_id, user_id))`.
  - `revoke all on public.messages, public.chats, public.chat_reads, public.chat_mutes from public, anon, authenticated, service_role` (K-S5).
  - `private.current_occurrence(p_series uuid) returns public.plans` — the series' plan with no successor (`not exists (select 1 from public.plans n where n.repeats_from = p.id)`), latest `starts_at` on a tie.
  - `private.chat_member(p_series uuid, p_user uuid) returns boolean` — on the current occurrence: `private.is_host(plan, p_user)` or an attendee row with `response in ('accepted','maybe')` (CH-P2 one-off rule; plan 2 replaces it for groups).
  - `private.chat_members(p_series uuid) returns setof uuid` (K-S4): the candidates are `private.host_ids(<current occurrence>)` and the attendees of the current occurrence, filtered by `private.chat_member(p_series, <id>)`. Every fan-out, audience and count uses it. Plan 2 changes only `chat_member`.
  - `private.chat_closes_at(p_series uuid) returns timestamptz`: `private.plan_end(starts_at, ends_at) + interval '48 hours'` on the current occurrence, or null when it is cancelled (CH-P15). A null means "no close time" (Shared interfaces). On a one-off that happens only when it was cancelled, so the chat is closed (CH-R-A2). Plan 2 returns null for a running group.
  - `private.chat_open(p_series uuid) returns boolean`: `coalesce(now() < private.chat_closes_at(p_series), <current occurrence>.status <> 'cancelled')`. Plan 2 redefines it for groups: a null close time on a group means open (CH-R-A2, NOTE 1).
  - `private.chat_is_group(p_series uuid) returns boolean`: `coalesce((select c.is_group from public.chats c where c.series_id = p_series), false)`, reading the column directly (CH-R-A6).
