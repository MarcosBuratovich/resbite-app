# UX2 (Maybe, Guest List After Answering, Narrower Notifications, Cover Descriptions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the UX2 server rules and the app changes that use them: a Maybe answer, a guest list shown only after answering, change notices only for a new time or place and only to people who may still come, wording-ready notification records, and cover photo descriptions. The plan also settles the three open UX1 choices.

**Architecture:**
- **One hosted-compatible migration, `20261014120000_ux2_rules.sql`, built in four reviewed slices (Tasks 1–4).**
  - It touches only objects that the eight hosted migrations create.
  - Its tests live in a new `supabase/tests/ux2.sql`, one rolled-back block per slice, run in full and hosted-baseline modes.
  - Task 5 adds a rollback script, which the hosted rehearsal proves restores the exact pre-UX2 definitions.
- **One local-only migration, `20261014130000_ux2_notification_wording.sql` (Task 6).** It extends the unreleased delivery functions. The sender's copy is a pure function in `_shared/notification-copy.ts` (Task 7).
- **App work starts with pure domain helpers (Task 8).** Then come the event page (Task 9), the edit landing and heading (Task 10), and the photo description (Task 11). The description gets its own small save and RPC. The database clears it whenever the photo changes, so the live photo-change machinery shared with profile photos is untouched.
- **Hosted rollout is not a task.** The controller does it after the final review, and each live change waits for the owner's explicit approval (see "Rollout").

**Tech Stack:** PostgreSQL 17 (local disposable cluster via `scripts/test-database.sh`), Supabase RLS and storage policies, Deno-style edge function code tested with Node 22 `node:test`, Expo SDK 57, React Native 0.86, expo-router 57 (typed routes), react-native-web 0.21, Playwright browser checks with intercepted Supabase.

**Spec:** `docs/superpowers/specs/2026-10-14-ux2-design.md`, approved by the owner on 14 October 2026 and amended while planning. The amendment changes the cover description mechanism, the preview line and the migration names; the owner confirms it with this plan.

## Review Focus

1. **An unanswered invitee reaching co-guests another way:**
   - through `profiles` (names), the avatar storage policy (photos), or `attendees` filtered by `user_id`;
   - expected: nothing beyond the organizer and themselves;
   - pinned by Task 3, block 3 of `ux2.sql` (profiles, avatar object and per-user attendee reads as a pending invitee).
2. **Edits that look like changes but aren't, and changes that don't look like it:**
   - re-saving the same instant, padding the same place with spaces (no notice);
   - changing only the time zone at the same instant (a `time` notice, because the shown time moves);
   - pinned by Task 2, block 2.
3. **People who said Can't make it:**
   - declined and withdrawn invitees still see the guest list (they answered) and still hear about a cancellation, but get no change notice, even if they switch back to Going after a change was queued;
   - the send-time recheck covers the reverse: Going at queue time, Can't make it at send time;
   - pinned by Task 2, block 2, Task 3, block 3, and Task 6.
4. **The photo changes on another device while the description sheet is open:**
   - expected: the save is refused as a conflict, the sheet keeps the typed text, and the message asks to reopen;
   - a retried save after a lost reply is accepted only with the same text;
   - pinned by Task 4, block 4 (SQL), and Task 11 (`verify-covers.mjs` conflict case).
5. **The guest list fails to load right after an answer is saved:**
   - expected: the answer stays confirmed, a message says who's coming couldn't load, and Refresh recovers;
   - the page never shows the full guest list without a confirmed answer, and never hides the confirmed answer;
   - pinned by Task 9 (`verify-event.mjs` guest-reload failure case).

## Decisions this plan makes

- **Cover description mechanism.** This is the spec amendment, for the owner to confirm.
  - A separate `set_plan_cover_description` RPC with a revision compare-and-swap.
  - `track_cover_revision` clears the description on any photo change.
  - `set_plan_cover_if_current` and the shared `finishVersionedPhotoChange` machinery stay byte-for-byte unchanged.
- **Where the "Describe photo" chip sits.** It's a chip directly below the photo tile, never over the photo (spec principle 5).
- **How the description is read aloud:**
  - On the static event-page card, the picture is an accessible image labelled with the description.
  - On pressable My resbites cards, the card label ends with "Photo: <description>".
  - On Review, the picture button reads "Edit photo, <description>".
  - The Invite screen's static card uses the editor's description.
- **Hidden guest area.** It shows the organizer's initial with the label "<name> is organizing", plus "Answer to see who’s coming". This needs one extra read of the organizer's profile, which the existing rule already allows.
- **Avatar stack label:** "N going", or "N going, M maybe" when anyone said Maybe.
- **After an edit, the editor returns with `router.dismissTo("/event", …)`.** Expo-router pops back to the existing event screen and merges the params. If the editor wasn't opened from an event page, it replaces the editor.
  - My resbites no longer shows "Changes saved".
  - The `updated` param is removed. Discard still returns to My resbites.
- **The migration's attendee-answer constraint is replaced by exact name.** If the live name differs, the migration fails instead of leaving two checks; the before-snapshot confirms the name first.
- **`public.create_plan` (v1) stays callable,** because it doesn't notify. Only `change_plan` (v1) is switched off.
- **The description has no device journal.**
  - If a new event's photo upload is left pending (the existing "hasn’t uploaded yet" notice), the description typed with it isn't saved. After "Retry cover", the organizer describes the photo again.
  - A failed description save after a successful photo upload says so: `coverNotice("description")`.
- **Validated while planning.** All SQL in Tasks 1–6 was assembled in a scratch copy of `supabase/` and passed both `./scripts/test-database.sh` modes, including the rollback proof. Deliberately breaking the rollback made the rehearsal fail with "Rollback did not restore grants". Task 7 passed 56 worker tests, and Task 8 passed its unit tests and `tsc`. Tasks 9–11 (screens and browser checks) were not pre-run.

```sql
-- UX2 rules (docs/superpowers/specs/2026-10-14-ux2-design.md): Maybe, who gets notified and what is
-- recorded, the guest list after answering, cover descriptions, and the old edit function switched off.
-- Hosted-compatible: depends only on the migrations listed in supabase/tests/hosted-baseline/migrations.txt.
-- Rollback: supabase/rollback/20261014120000_ux2_rules.rollback.sql.

-- Maybe (UX-P3). Replaced by exact name: if the live name differs, this fails instead of leaving two checks.
alter table public.attendees drop constraint attendees_response_check;
alter table public.attendees add constraint attendees_response_check
 check (response in ('pending','accepted','maybe','declined','withdrawn'));

-- What happened and who did it, for the notification wording (UX2-D4). Rows queued before UX2 keep nulls.
alter table private.notification_outbox
 add column actor_id uuid references public.profiles(id) on delete set null,
 add column detail text,
 add constraint notification_outbox_detail_check check (
  detail is null
  or (kind='plan_changed' and detail in ('time','place','time_place'))
  or (kind='rsvp' and detail in ('accepted','maybe','declined','withdrawn')));
create index notification_outbox_actor_idx on private.notification_outbox(actor_id);

-- Maybe is an answer; each answer records who answered and what. Otherwise the foundation body.
create or replace function private.respond(p_plan uuid,p_response text,p_version integer) returns integer language plpgsql security definer set search_path = '' as $$
declare v_uid uuid := private.require_tester(); v_plan public.plans; v_att public.attendees; v_next integer;
begin
 select * into v_plan from public.plans where id=p_plan for update;
 select * into v_att from public.attendees where plan_id=p_plan and user_id=v_uid for update;
 if v_att.user_id is null then raise exception 'Invitee required' using errcode='42501'; end if;
 if v_plan.status<>'active' or v_plan.starts_at<=now() then raise exception 'Plan unavailable' using errcode='22023'; end if;
 if p_response is null or p_response not in ('accepted','maybe','declined','withdrawn') then raise exception 'Invalid response' using errcode='22023'; end if;
 if p_version is distinct from v_att.version then
  if v_att.response=p_response and p_version=v_att.version-1 then return v_att.version; end if;
  raise exception 'Response changed; refresh' using errcode='40001';
 end if;
 if v_att.response=p_response then return v_att.version; end if;
 v_next:=v_att.version+1;
 update public.attendees set response=p_response,version=v_next,updated_at=now() where plan_id=p_plan and user_id=v_uid;
 insert into private.notification_outbox(plan_id,recipient_id,kind,dedupe_key,actor_id,detail)
 values(p_plan,v_plan.owner_id,'rsvp','rsvp:'||p_plan||':'||v_uid||':'||v_next,v_uid,p_response) on conflict do nothing;
 return v_next;
end $$;

-- A claim records the person claiming. Otherwise the 20261007210000_claim_notifies_owner body.
create or replace function private.claim_invite(p_token text) returns uuid language plpgsql security definer set search_path = '' as $$
declare v_uid uuid := private.require_tester(); v_inv private.invitations; v_plan public.plans; v_id uuid;
begin
 -- Lock plan before invitation consistently with cancellation/revocation.
 select plan_id into v_id from private.invitations where token_hash=extensions.digest(p_token,'sha256');
 select * into v_plan from public.plans where id=v_id for update;
 select * into v_inv from private.invitations where token_hash=extensions.digest(p_token,'sha256') for update;
 if v_inv.id is null or v_plan.status<>'active' or v_plan.starts_at<=now() or v_inv.revoked_at is not null or (v_inv.claimed_by is not null and v_inv.claimed_by<>v_uid) then raise exception 'Invitation unavailable' using errcode='42501'; end if;
 if v_plan.owner_id=v_uid then raise exception 'Owner cannot claim own invitation' using errcode='22023'; end if;
 if v_inv.intended_email is not null and not exists(select 1 from auth.users where id=v_uid and lower(email)=v_inv.intended_email and email_confirmed_at is not null) then raise exception 'Invitation unavailable' using errcode='42501'; end if;
 if v_inv.claimed_by=v_uid then return v_inv.plan_id; end if;
 update private.invitations set claimed_by=v_uid where id=v_inv.id;
 insert into public.attendees(plan_id,user_id) values(v_inv.plan_id,v_uid) on conflict do nothing;
 insert into private.notification_outbox(plan_id,recipient_id,kind,dedupe_key,actor_id) values(v_inv.plan_id,v_plan.owner_id,'invitation','invite:'||v_inv.id,v_uid) on conflict do nothing;
 return v_inv.plan_id;
end $$;
```

-- themselves until they answer (Going, Maybe or Can't make it), then everyone. Names and profile photos
-- follow the same rule, because the avatar storage policy calls can_read_profile.
create function private.can_see_guests(p_plan uuid) returns boolean language sql stable security definer set search_path = '' as $$
 select private.eligible() and exists(select 1 from public.plans p where p.id=p_plan and (p.owner_id=auth.uid()
  or exists(select 1 from public.attendees a where a.plan_id=p.id and a.user_id=auth.uid() and a.response<>'pending')))

create or replace function private.track_cover_revision() returns trigger
language plpgsql security invoker set search_path='' as $$
begin
 if tg_op='INSERT' then
  new.cover_revision := 0;
 else
  if new.cover_path is distinct from old.cover_path then
   new.cover_description := '';
  end if;
  if new.cover_path is distinct from old.cover_path or new.cover_description is distinct from old.cover_description then
   new.cover_revision := old.cover_revision + 1;
  else
   new.cover_revision := old.cover_revision;
  end if;
 end if;
 return new;
end $$;

 select d.id from private.notification_deliveries d where d.state in ('pending','ticket')

 order by d.next_attempt_at,d.id limit greatest(1,least(coalesce(p_limit,25),25)) for update skip locked
 ), claimed as (
 update private.notification_deliveries d set lease_id=gen_random_uuid(),lease_until=now()+interval '2 minutes',
 attempts=d.attempts+1,state=case when d.ticket_id is null then 'sending' else 'ticket' end

 )

/**
 * UX2 notification text (spec "Notification wording", UX2-D4). The heading is the event title and the body
 * says what happened and who did it. It never contains the place, the note, the description or the cover
 * description. Anything missing or unexpected falls back to the generic text.
 */
export type CopyInput = {
  kind?: string | null;
  detail?: string | null;
  title?: string | null;
  starts_at?: string | null;
  time_zone?: string | null;
  actor_name?: string | null;
};
export type Copy = { title: string; body: string };
export const GENERIC_COPY: Copy = Object.freeze({
  title: "Resbite",
  body: "You have an update. Open Resbite to see it.",
});

/** "Sat 17 Oct, 10:00" in the event's own time zone, or null if the time or zone is unusable. */
function eventTime(startsAt: string | null | undefined, zone: string | null | undefined): string | null {
  if (!startsAt || !zone) return null;
  const date = new Date(startsAt);
  if (!Number.isFinite(date.getTime())) return null;
  try {
    return new Intl.DateTimeFormat("en-GB", {
      weekday: "short",
      day: "numeric",
      month: "short",
      hour: "2-digit",
      minute: "2-digit",
      hourCycle: "h23",
      timeZone: zone,
    }).format(date);
  } catch {
    return null;
  }

      return "might come.";

function body(input: CopyInput): string | null {
  const name = input.actor_name?.trim();
  switch (input.kind) {
    case "rsvp": {
      const said = answer(input.detail);
      return name && said ? `${name} ${said}` : null;
    }

      return name ? `${name} joined from your invite.` : null;
    case "plan_cancelled":
      return "This resbite was cancelled.";

      if (input.detail === "time") return `New time: ${time}.`;
      if (input.detail === "time_place") return `New time: ${time}, and a new place.`;

    }
    default:
      return null;
  }
}

  const text = title ? body(input) : null;
  return title && text ? { title, body: text } : GENERIC_COPY;
}

    async read(): Promise<CoverDescription | null> {
      const bound = await client();

        bound
          .from("plans")
          .select("cover_path,cover_description,cover_revision")
          .eq("id", planId)

          .maybeSingle(),

            p_plan: planId,

import * as Crypto from "expo-crypto";
import { useApp } from "./AppState";
import { chooseNormalizedPhoto } from "../services/photo";
import {
  CoverDescriptionConflict,
  coverDescriptionGateway,
  coverGateway,
  planCoverStore,
  signedCovers,
} from "../services/planCovers";
import { finishVersionedPhotoChange, type PhotoChange } from "../services/profilePhotoStore";
import {
  COVER_DESCRIPTION_MAX,
  COVER_MAX_DIMENSION,
  coverPhotoLayout,
  coverScope,
  coverTarget,
} from "../domain/covers";

export type CoverOutcome = "none" | "saved" | "pending" | "failed" | "description";
export type CoverControls = {
  uri: string | null;
  /** UX2: the photo description VoiceOver reads; "" when there is none. */
  description: string;
  pending: PhotoChange | null;
  busy: boolean;
  ready: boolean;
  message: string | null;
  choose(): Promise<void>;
  remove(): Promise<void>;
  retry(): Promise<void>;
  keep(): Promise<void>;
  /** Saves the description (or holds it until the resbite exists). Resolves to an error message, or null. */
  describe(text: string): Promise<string | null>;
  commitAfterCreate(planId: string): Promise<CoverOutcome>;
};

const DESCRIPTION_TOO_LONG = "Keep the description to 200 characters.";
const DESCRIPTION_CONFLICT = "The photo changed elsewhere. Reopen this resbite, then describe it again.";
const DESCRIPTION_UNCONFIRMED = "The photo description didn’t save. Check your connection and try again.";

/**
 * Cover photo for the plan editor (CE2), with its description (UX2).
 * - New resbite: a chosen cover and its description stay on the device; the cover uploads after the plan
 *   is created, then the description is saved.
 * - Existing resbite: changes apply at once through the versioned cover pointer; a new or removed photo
 *   clears its description (the database does the same).
 * - Preview: covers and descriptions stay in memory.
 */
export function useCoverPhoto(options: {
  planId: string | null;
  preview: boolean;
  previewUri?: string | null;
  previewDescription?: string;
  onPreviewChange?: (uri: string | null) => void;
  onPreviewDescribe?: (description: string) => void;
}): CoverControls {
  const { planId, preview, onPreviewChange, onPreviewDescribe } = options;
  const { session, captureSession } = useApp();
  const ownerId = session?.user.id ?? null;
  const scope = (() => {
    if (preview || !ownerId || !planId) return null;
    try {
      return coverScope(ownerId, planId);
    } catch {
      return null;
    }
  })();
  const [uri, setUri] = useState<string | null>(preview ? (options.previewUri ?? null) : null);
  const [description, setDescriptionState] = useState(preview ? (options.previewDescription ?? "") : "");
  const [pending, setPending] = useState<PhotoChange | null>(null);
  const [busy, setBusy] = useState(false);
  const [ready, setReady] = useState(preview || !planId);
  const [message, setMessage] = useState<string | null>(null);
  const saved = useRef<{ path: string | null; revision: number }>({ path: null, revision: 0 });
  const chosen = useRef<{ bytes: Uint8Array; uri: string } | null>(null);
  // The latest description, for commitAfterCreate, which runs outside a render.
  const described = useRef(description);
  const setDescription = (text: string) => {
    described.current = text;
    setDescriptionState(text);
  };
  const working = useRef(false);
  const mounted = useRef(true);
  useEffect(() => {
    mounted.current = true;
    return () => {
      mounted.current = false;
    };
  }, []);
  const guard = useCallback(() => {
    const assertSession = captureSession();
    return () => {
      assertSession();
      if (!mounted.current) throw Error("Cover change cancelled.");
    };
  }, [captureSession]);

  // Existing resbite: the server is the truth for the saved cover; a journal means a change needs confirmation.
  useEffect(() => {
    if (!scope || !ownerId || !planId) return;
    let active = true;
    setReady(false);
    setMessage(null);
    void (async () => {
      try {
        const journal = await planCoverStore.read(scope);
        const current = await coverDescriptionGateway(ownerId, planId).read();
        if (!current) throw Error(coverPhotoLayout.copy.missing);
        const next = current.path ? await signedCovers.get(current.path) : null;
        if (!active) return;
        saved.current = { path: current.path, revision: current.revision };
        setPending(journal);
        setUri(next);
        setDescription(current.description);
        setReady(true);
      } catch {
        if (active) setMessage("The cover photo needs a connection. Reopen this plan to try again.");
      }
    })();
    return () => {
      active = false;
    };
  }, [scope, ownerId, planId]);

  async function run(action: (check: () => void) => Promise<void>) {
    if (working.current) return;
    let check: () => void;
    try {
      check = guard();
    } catch {
      return;
    }
    working.current = true;
    setBusy(true);
    setMessage(null);
    try {
      await action(check);
    } catch (e) {
      if (mounted.current)
        setMessage(e instanceof Error ? e.message : coverPhotoLayout.copy.unconfirmed);
    } finally {
      working.current = false;
      if (mounted.current) setBusy(false);
    }
  }
  async function finish(change: PhotoChange, check: () => void) {
    const result = await finishVersionedPhotoChange(
      change,
      coverGateway(ownerId!, planId!),
      () => planCoverStore.bytes(scope!),
      check,
      coverPhotoLayout.copy,
    );
    check();
    saved.current = { path: result.path, revision: result.revision };
    const next = result.path ? await signedCovers.get(result.path) : null;
    check();
    await planCoverStore.clear(scope!);
    setUri(next);
    // The database cleared the previous photo's description.
    setDescription("");
    setPending(null);
    setMessage(
      (result.path ? "Cover photo saved." : "Cover photo removed.") +
        (result.cleanupPending
          ? " The previous file stays in private storage until cleanup is available."
          : ""),
    );
  }
  async function apply(target: string | null, bytes: Uint8Array | null, check: () => void) {
    const change: PhotoChange = {
      previous: saved.current.path,
      target,
      expectedRevision: saved.current.revision,
    };
    await planCoverStore.begin(scope!, change, bytes, check);
    check();
    setPending(change);
    await finish(change, check);
  }
  const choose = () =>
    run(async (check) => {
      const photo = await chooseNormalizedPhoto(COVER_MAX_DIMENSION);
      check();
      if (!photo) return;
      if (preview) {
        setUri(photo.uri);
        onPreviewChange?.(photo.uri);
        setDescription("");
        onPreviewDescribe?.("");
        setMessage("Preview cover stays in memory. Nothing is uploaded.");
        return;
      }
      if (!planId) {
        chosen.current = photo;
        setUri(photo.uri);
        setDescription("");
        setMessage("Your cover uploads after the resbite is saved.");
        return;
      }
      await apply(coverTarget(scope!, Crypto.randomUUID()), photo.bytes, check);
    });
  const remove = () =>
    run(async (check) => {
      if (preview) {
        setUri(null);
        onPreviewChange?.(null);
        setDescription("");
        onPreviewDescribe?.("");
        return;
      }
      if (!planId) {
        chosen.current = null;
        setUri(null);
        setDescription("");
        return;
      }
      await apply(null, null, check);
    });
  const retry = () =>
    run(async (check) => {
      if (pending) await finish(pending, check);
    });
  const keep = () =>
    run(async (check) => {
      const current = await coverDescriptionGateway(ownerId!, planId!).read();
      check();
      if (!current) throw Error(coverPhotoLayout.copy.missing);
      saved.current = { path: current.path, revision: current.revision };
      const next = current.path ? await signedCovers.get(current.path) : null;
      check();
      await planCoverStore.clear(scope!);
      setUri(next);
      setDescription(current.description);
      setPending(null);
      setMessage("Keeping the saved cover. An unused uploaded file may remain until cleanup is available.");
    });
  async function describe(text: string): Promise<string | null> {
    const next = text.trim();
    if (next.length > COVER_DESCRIPTION_MAX) return DESCRIPTION_TOO_LONG;
    if (preview) {
      setDescription(next);
      onPreviewDescribe?.(next);
      return null;
    }
    // Before the resbite exists, the description waits with the chosen photo (commitAfterCreate).
    if (!planId) {
      setDescription(next);
      return null;
    }
    if (working.current || !ownerId) return DESCRIPTION_UNCONFIRMED;
    let check: () => void;
    try {
      check = guard();
    } catch {
      return DESCRIPTION_UNCONFIRMED;
    }
    working.current = true;
    setBusy(true);
    setMessage(null);
    try {
      const result = await coverDescriptionGateway(ownerId, planId).save(next, saved.current.revision);
      check();
      saved.current = { path: result.path, revision: result.revision };
      setDescription(result.description);
      setMessage(result.description ? "Photo description saved." : "Photo description removed.");
      return null;
    } catch (e) {
      // A lost reply is safe to retry: the same text at the next revision is acknowledged.
      return e instanceof CoverDescriptionConflict ? DESCRIPTION_CONFLICT : DESCRIPTION_UNCONFIRMED;
    } finally {
      working.current = false;
      if (mounted.current) setBusy(false);
    }
  }
  async function commitAfterCreate(newPlanId: string): Promise<CoverOutcome> {
    const photo = chosen.current;
    if (preview || !photo || !ownerId) return "none";
    let check: () => void;
    let newScope: string;
    try {
      check = guard();
      newScope = coverScope(ownerId, newPlanId);
    } catch {
      return "failed";
    }
    const change: PhotoChange = {
      previous: null,
      target: coverTarget(newScope, Crypto.randomUUID()),
      expectedRevision: 0,
    };
    try {
      await planCoverStore.begin(newScope, change, photo.bytes, check);
    } catch {
      return "failed";
    }
    try {
      const result = await finishVersionedPhotoChange(
        change,
        coverGateway(ownerId, newPlanId),
        () => planCoverStore.bytes(newScope),
        check,
        coverPhotoLayout.copy,
      );
      await planCoverStore.clear(newScope);
      chosen.current = null;
      // The description waits for its photo; if it fails, the photo stays saved without it.
      const text = described.current;
      if (!text) return "saved";
      try {
        await coverDescriptionGateway(ownerId, newPlanId).save(text, result.revision);
        return "saved";
      } catch {
        return "description";
      }
    } catch {
      return "pending";
    }
  }
  return { uri, description, pending, busy, ready, message, choose, remove, retry, keep, describe, commitAfterCreate };
}
