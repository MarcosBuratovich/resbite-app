# GI1 (One Link per Event and the Web Event Page) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every resbite one shareable link that opens a web page with the basics (host, title, time, area, count, image) and an RSVP button, opens the app on the invitation when it is installed, and lets the host turn the link off, set an area, and remove a guest.

**Architecture:**
- **One hosted-compatible migration, `20261021120000_gi1_event_links.sql` (Task 1)**: the `private.plan_links` table and its owner-only functions, the `plans.area` column with the save functions taking `p_area`, the public `invitation_page(code)` read and `claim_plan_link(code)`. Task 2 adds its rollback and the hosted rehearsal.
- **The web page (Task 3)** is two small Node functions in `links/server/` that the existing generator copies into the `resbite-link` Vercel project: `/r/<code>` renders the page from `invitation_page`, `/r/<code>/image` serves the cover, illustration or mark. No secret in the repo; the keys are Vercel environment variables.
- **The app (Tasks 4–9)**: the link parser and pending store learn event codes; the data layer sends `p_area` and calls the four new RPCs; the Where step gets the Area field; the Invitations screen becomes the event's link; the guest list gets Remove; `/invite` claims by code.
- **Hosted rollout, the Vercel deployment and the TestFlight build are not tasks.** The controller and the owner do them after the final review, each live change with the owner's explicit approval (see "Rollout").

**Tech Stack:** PostgreSQL 17 (local disposable cluster via `scripts/test-database.sh`), Supabase RLS and PostgREST RPC, Node 22 (`node:test`) for the page functions, Vercel serverless functions (Node runtime), Expo SDK 57 / React Native 0.86 / expo-router 57 with typed routes, Playwright browser checks with intercepted Supabase.

**Spec:** `docs/superpowers/specs/2026-10-21-gi1-event-links-design.md`, approved by the owner on 21 October 2026. This plan amends it in two places (decisions P1 and P2), which the owner confirms with this plan.

## Review Focus

1. **A link forwarded beyond the group, opened by someone the host never meant to invite:**
   - expected: they see the host, title, time, area, count and image, and nothing else; the exact place, Meeting details, the note and names stay hidden until they have an account and have replied;
   - pinned by Task 1 (`gi1.sql` block 2: the JSON never contains the place, note, description or names, and has exactly nine keys) and Task 3 (`page.test.mjs`: extra keys never reach the page or its preview).
2. **The host turns the link off while someone still has the page open and taps RSVP:**
   - expected: the old link's page and the app both say the invitation is no longer active, and the new link works;
   - pinned by Task 1 (block 1: the old code reads `inactive`; block 3: joining with an unknown code is refused) and Task 8 (opening an inactive code in the app shows the error text).
3. **An organizer on build 8 edits an event that already has an area:**
   - expected: the area survives the edit, because the old build never sends it;
   - pinned by Task 1 (block 3: an edit without `p_area` keeps the area; a v2 edit keeps it).
4. **The host removes a guest who still has the link:**
   - expected: the guest leaves the event and their per-person links stop working; the event link stays open (removal is not a ban), so they could rejoin, which the ⓘ sheet says;
   - pinned by Task 1 (block 1: `remove_guest` deletes the attendee, revokes their claimed per-person invitation, ignores strangers, refuses the organizer; `rotate_plan_link` revokes the unclaimed per-person links) and Task 8 (`verify-event`: Remove with confirmation).
5. **The organizer taps their own event's link in the group chat:**
   - expected: the app opens their event page, not an error;
   - pinned by Task 1 (block 3: the organizer's claim returns the plan id, adds no attendee and queues no notice) and Task 8 (`invite.tsx` lands on the event page).

## Decisions this plan makes

- **P1. Spec amendment: the organizer opening their own link lands on the event.** The spec mirrored `claim_invite` (22023 for the organizer). A host will tap their own link in the chat they just posted it in; an error there is wrong. `claim_plan_link` returns the plan id for the organizer, adds nothing and notifies nobody.
- **P2. Spec amendment: `public.invitation_page` is a definer wrapper.** The spec's pattern is an invoker wrapper over a definer body; `anon` has no usage on the `private` schema, so the wrapper for the one anonymous function is a definer too. It returns only what the private body returns.
- **P3. The page server fails closed.** A database error or timeout renders the "no longer active" page with the generic preview; nothing is cached, so the next request tries again.
- **P4. The image route streams the cover** (through a signed URL valid for minutes, made with the Vercel-only secret) rather than redirecting, so the preview address stays stable and the signed URL never leaves the server.
- **P5. The RSVP sheet opens without JavaScript** (a `:target` sheet), and the page's only script shows "If Resbite doesn’t open, install it first." after "I have Resbite: open the app" when the page is still visible 1.5 s later.
- **P6. "Get the app" points at the TestFlight invitation link** (`APP_STORE_URL`) until the app is public; the smart app banner is off (`APP_STORE_ID` empty) until then, because Safari only shows it for App Store apps.
- **P7. Illustrations ship with the site.** The generator copies `mobile/assets/activities/*.png` into the deployed folder, so the image route serves them from disk with no database or storage call.
- **P8. Removal revokes the guest's per-person links too**, so a link shared before GI1 can't bring them straight back; the event link can, by design.
- **P10. "Turn off this link" also turns off the event's unclaimed per-person links** (shared before GI1), because the per-person Revoke is gone and the host would otherwise have no way to stop one. Claimed ones belong to guests, whom Remove handles (P8). The ⓘ sheet says so.
- **P11. People is no longer an entry point to Invite people.** Its only link was "Review invitations", which belonged to the per-person flow; the two entry points that matter (after creating an event, and "Invite someone" on the event page) stay. The spec listed People among the entry points; this plan drops it.
- **P12. The share text's date is in the phone's time zone**, like every card in the app; the web page uses the event's time zone. For a host sharing their own event the two agree.
- **P9. Old links and the old page stay.** `/invite#token=` and `claim_invite` keep working for links already shared; only the organizer screen stops making them.

### Task 1: The migration: event links, the area, the public read and joining by code

**Files:**
- Create: `supabase/migrations/20261021120000_gi1_event_links.sql`
- Create: `supabase/tests/gi1.sql`

**Interfaces:**
- Produces (database):
  - `private.plan_links(id, plan_id → plans on delete cascade, code text unique, created_at, revoked_at)`; at most one row per plan with `revoked_at is null`; no client access.
  - `public.plan_link(p_plan uuid) returns text`: the active 22-character code, made on first call. `public.rotate_plan_link(p_plan uuid) returns text`: revokes the active link and the event's unclaimed per-person invitations, returns a new code. `public.remove_guest(p_plan uuid, p_user uuid) returns void`. All three: the organizer of an active event that hasn't started, else `42501` "Active plan owner required"; removing the organizer raises `22023`; removing a stranger does nothing.
  - `public.plans.area text not null default ''` (trimmed, at most 80 characters).
  - `public.create_plan_v3(…, p_lon double precision default null, p_area text default null)` and `public.change_plan_v3(…, p_cancel boolean default false, p_area text default null)`: `null` leaves the area unchanged (builds up to 8 never send it), `''` clears it, text sets it trimmed. The old 12- and 11-argument signatures are gone; `create_plan_v2` / `change_plan_v2` are untouched and never touch the area.
  - `public.invitation_page(p_code text) returns jsonb`, callable by `anon` and `authenticated`: `{state:'inactive'}` for an unknown, revoked or malformed code; `{state:'cancelled'|'happened', host, title}`; or `{state:'open', host, title, starts_at, ends_at, time_zone, area, going, image:{kind:'cover'|'activity'|'mark', ref}}`. `going` counts Going only. Exactly nine keys when open.
  - `public.claim_plan_link(p_code text) returns uuid`: joins the event as `pending` and queues one `invitation` notice to the organizer (dedupe `link:<link id>:<user>`); idempotent; the organizer gets the plan id back with no row and no notice; `42501` "Invitation unavailable" for an unknown, revoked, malformed code or a cancelled or started event.
  - The redaction trigger also blanks `area`.

// invitation_page returns, so nothing else about an event can reach the page or its preview.
export const PAGE_CSP =
  "default-src 'none'; img-src 'self'; script-src 'self'; style-src 'self'; base-uri 'none'; form-action 'none'; connect-src 'none'; frame-ancestors 'none'";

/** The headers every rendered page carries. */
export function pageHeaders() {
  return {
    "Content-Type": "text/html; charset=utf-8",
    "Cache-Control": "no-store",
    "Referrer-Policy": "no-referrer",
    "Content-Security-Policy": PAGE_CSP,
    "X-Content-Type-Options": "nosniff",
    "X-Robots-Tag": "noindex, nofollow",
  };
}

export const CODE_PATTERN = /^[A-Za-z0-9_-]{22}$/;
export const isLinkCode = (value) => typeof value === "string" && CODE_PATTERN.test(value);

const escape = (text) =>
  String(text ?? "").replace(/[&<>"']/g, (c) => ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" })[c]);

/** "Fri 23 Oct, 19:30 – 22:00" in the event's own time zone, as the app shows it; "Fri 23 Oct, 19:30" without an end. */
export function formatWhen(startsAt, endsAt, timeZone) {
  const start = new Date(startsAt);
  if (Number.isNaN(start.getTime())) return "";
  let zone = timeZone || "UTC";
  try {
    new Intl.DateTimeFormat("en-GB", { timeZone: zone });
  } catch {
    zone = "UTC";
  }
  const day = new Intl.DateTimeFormat("en-GB", { weekday: "short", day: "numeric", month: "short", timeZone: zone });
  const time = new Intl.DateTimeFormat("en-GB", { hour: "2-digit", minute: "2-digit", hour12: false, timeZone: zone });
  const clock = (date) => time.format(date).replace(/^24:/, "00:");
  const end = endsAt ? new Date(endsAt) : null;
  const range = end && !Number.isNaN(end.getTime()) && end > start ? `${clock(start)} – ${clock(end)}` : clock(start);
  return `${day.format(start)}, ${range}`;
}

// The page server's two database calls (GI1). The publishable key can only call invitation_page; the secret key
// is used for one thing, signing a short-lived URL for an event's cover photo, and lives only on Vercel.
import { isLinkCode } from "./render.mjs";

const need = (name) => {
  const value = process.env[name];
  if (!value) throw Error(`${name} is not set`);
  return value;
};

/** Calls public.invitation_page(code). Malformed codes never reach the database. */
export async function readInvitationPage(code, fetchImpl = fetch) {
  if (!isLinkCode(code)) return { state: "inactive" };
  const url = need("SUPABASE_URL"),
    key = need("SUPABASE_PUBLISHABLE_KEY");
  const response = await fetchImpl(`${url}/rest/v1/rpc/invitation_page`, {
    method: "POST",
    headers: { apikey: key, Authorization: `Bearer ${key}`, "Content-Type": "application/json" },
    body: JSON.stringify({ p_code: code }),
  });
  if (!response.ok) throw Error(`invitation_page ${response.status}`);
  const data = await response.json();
  return data && typeof data === "object" && typeof data.state === "string" ? data : { state: "inactive" };
}

/** A signed URL for a cover photo, valid for `expiresIn` seconds; null when the storage call fails. */
export async function signCoverUrl(path, expiresIn = 300, fetchImpl = fetch) {
  if (typeof path !== "string" || !/^[A-Za-z0-9/_.-]{1,300}$/.test(path) || path.includes("..")) return null;
  const url = need("SUPABASE_URL"),
    key = need("SUPABASE_SECRET_KEY");
  const response = await fetchImpl(`${url}/storage/v1/object/sign/plan-covers/${path}`, {
    method: "POST",
    headers: { apikey: key, Authorization: `Bearer ${key}`, "Content-Type": "application/json" },
    body: JSON.stringify({ expiresIn }),
  });
